## Position

T1의 네 gate와 `baseline → candidate replay → compare → human decision → retain` 구조는 유지한다. 다만 첫 closed-loop proof에는 한 가지 **비자명성 조건**이 더 필요하다.

`PASS → PASS → no-change`만 관찰해도 정상 작동으로 인정하면, 실제로는 모든 output을 PASS시키는 무의미한 rubric도 같은 모양의 proof를 만들 수 있다. 따라서 첫 proof에서는 **같은 task-quality rubric이 traced model output 하나 이상을 실제 `FAIL`로 분류할 수 있음을 관찰해야 한다.**

이 요구는 candidate가 반드시 개선되어야 한다는 뜻이 아니다.

```text
Q1 + fixed rubric
→ traced run A = FAIL
→ candidate replay = PASS 또는 FAIL
→ compare
→ human accept / reject / no-change
→ Q1 retained
```

`FAIL → PASS`면 개선을 수용할 수 있고, `FAIL → FAIL`이면 candidate를 reject하거나 no-change로 둘 수 있다. 두 경우 모두 feedback loop는 정상 작동한다. 핵심은 loop가 부정 품질 신호를 실제로 만들어 내고 그 신호가 판단에 소비됐다는 점이다.

## Evidence

- [`docs/VISION.md`](../../../../docs/VISION.md)는 LLMOps에 `Evaluate and Regress`와 `Replay Failures`를 요구한다. 단순히 두 run이 존재한다는 것보다 실패한 판단이나 중요한 경계 사례를 평가·재실행 가능한 회귀 사례로 바꾸는 능력이 핵심이다.
- T1 synthesis는 human-authored binary rubric을 최소로 허용한다. 그렇다면 그 rubric이 최소 한 번 `FAIL`을 만들어 낼 수 있음을 보여 주지 않으면 `Quality-evaluable`이 실제 discrimination인지 형식적 checklist인지 구분할 수 없다.
- 이 조건은 별도 evaluator framework, LLM-as-judge 또는 세 번째 replay run을 요구하지 않는다. 기존 Q1과 두 run 안에서 증명할 수 있다.

## Counterexample

다음과 같은 잘못된 구현도 T1의 느슨한 형태만 보면 통과할 수 있다.

```text
rubric: 항상 PASS
baseline = PASS
candidate = PASS
human = no-change
case retained
```

Trace, compare, decision record는 모두 존재하지만 quality regression을 검출할 능력이 있는지는 전혀 증명되지 않는다. 이런 상태를 “LLMOps가 정상 작동한다”고 인정하면 `Quality-evaluable` gate가 실질적으로 비게 된다.

## Proposal

`Quality-evaluable`의 최초 proof pass condition을 다음처럼 좁힌다.

> 같은 versioned quality case와 rubric으로 traced model output을 평가했을 때, 최소 한 번은 material quality expectation 위반을 `FAIL`로 식별한 evidence가 존재한다.

이 `FAIL`은 baseline 또는 candidate 어디에서 나와도 된다. Candidate가 개선될 필요도 없다. 단, 사람이 임의로 만든 텍스트 fixture만 FAIL시키고 실제 model invocation은 모두 PASS인 상태는 end-to-end LLMOps proof로는 부족하다고 본다. 최소 한 번의 **traced model invocation**이 quality FAIL이어야 한다.

첫 Q1이 `root cause uncertainty`라면 가장 작은 negative signal은 다음과 같다.

- supplied evidence로 root cause를 확정할 수 없는데 review가 특정 원인을 사실처럼 단정함 → `FAIL`
- review가 그 불확실성을 material uncertainty로 드러냄 → `PASS`
