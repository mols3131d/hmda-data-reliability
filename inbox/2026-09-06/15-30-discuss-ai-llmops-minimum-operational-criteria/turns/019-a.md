## Outcome Candidate

`sublation`으로 마무리할 수 있다. B의 `018-b` finalization signal과 두 precision finding을 반영했으며, 현재 남은 material contradiction은 없다.

T7의 최종 proposition은 다음과 같다.

> Applicable candidate는 admissible quality decision evidence 없이 accept할 수 없다. Candidate가 material regression을 유발했다는 admissible attribution evidence가 있으면 그 failure는 human `reject`의 근거가 될 수 있다. Comparison validity 또는 attribution이 성립하지 않으면 `blocked/inconclusive`로 acceptance와 baseline promotion을 멈춘다. Blocker evidence는 candidate/applicability, case/basis, failure/attribution, baseline continuity와 revisit condition을 직접 또는 durable evidence chain으로 유일하게 재구성할 수 있어야 한다. Blocker 해소 후 같은 candidate를 다시 평가할 수 있지만 현재 조건에서 valid comparable evidence를 새로 성립시켜야 한다.

## Gate Semantics

```text
candidate acceptance event
→ applicability?
   → not-applicable:
        reconstructable non-applicability basis
   → applicable:
        retained case + current quality basis
        → admissible candidate-caused material regression evidence?
             → yes: reject is permitted as a human decision
             → no:
                  valid comparable quality evidence available?
                  → yes: compare → accept / reject / no-change
                  → no: blocked/inconclusive
                       → acceptance stops
                       → no baseline promotion
```

`not-applicable`은 quality evaluation obligation이 발생하지 않은 상태다. `blocked/inconclusive`는 obligation은 발생했지만 admissible decision evidence를 아직 만들 수 없는 상태다. 둘을 같은 `eval 없음`으로 압축하지 않는다.

`blocked`와 `inconclusive`는 별도 top-level state로 나누지 않는다. 실행 불가, evidence invalid, quality judgment insufficiency 같은 차이는 reason에서 보존한다.

## Reject Boundary

Failure status 이름만으로 reject 여부를 결정하지 않는다. `unavailable`, `validation_failed`, `input_rejected`, `provenance_failed`는 failure stage를 나타낼 뿐 candidate attribution을 자동 증명하지 않는다.

Candidate failure가 reject 근거가 되려면 다음이 필요하다.

- candidate와 failure 사이의 causal mechanism이 change evidence에서 직접 재구성되거나 materially equivalent conditions에서 candidate-specific이라는 bounded evidence가 있고,
- 그 failure가 retained quality expectation 또는 required operational behavior의 material violation이며,
- reject rationale로 사용할 attribution evidence 자체가 durable하게 보존된다.

Provider timeout처럼 shared/stochastic cause가 여전히 plausible한 한 번의 asymmetric observation만으로 reject를 추측하지 않는다. 이 경우 comparison validity 또는 attribution이 충분하지 않다면 `blocked/inconclusive`다.

Fixed retry count, statistical threshold 또는 significance test는 최소 contract로 정하지 않는다. Attribution sufficiency에는 bounded human judgment가 남는다.

## Blocked Boundary

다음은 candidate attribution이 별도로 입증되지 않는 한 `blocked/inconclusive`다.

- shared provider, credential 또는 environment failure
- provenance persistence failure로 durable comparison chain이 성립하지 않음
- replay/input equivalence failure
- baseline/candidate material case 또는 basis mismatch
- quality basis 또는 quality judgment basis가 현재 candidate를 admissibly 판정하기에 불충분함
- failure attribution이 현재 evidence로 inconclusive함

`independent oracle` 자체는 최소 요구가 아니다. Human rubric과 judgment도 T2/T3 contract 안에서 admissible quality judgment basis가 될 수 있다.

## Baseline Continuity

Blocked candidate에서는 baseline promotion이 일어나지 않는다. 마지막 accepted candidate가 durable decision baseline으로 남는다.

이 의미는 기존 baseline이 blocked 시점에 다시 품질 검증됐거나 operationally available하다는 보장이 아니다. Provider retirement 또는 shared outage로 기존 baseline도 현재 실행 불가능할 수 있다. T7이 보존하는 것은 decision lineage의 baseline identity다.

Blocker 해소 뒤 재평가할 때는 당시 blocked attempt의 partial evidence를 이어붙이지 않는다. 다음을 현재 조건에서 다시 확인한다.

- retained case/input과 quality basis가 같은 material question을 나타내는가
- current accepted baseline과 candidate가 materially comparable한가
- provider/model/config/environment 변화가 new invocation evidence에 반영됐는가
- 이전 blocked attempt에서 inadmissible했던 output/provenance를 새 evidence로 승격하지 않았는가

같은 candidate identity를 유지할 수 있어도 **comparison validity는 새로 성립**해야 한다. Blocked 동안 다른 candidate가 accept되어 baseline이 바뀌었다면 재평가 시 current accepted baseline을 다시 resolve한다.

## Minimum Durable Block Evidence

최소 blocker record는 다음 의미를 다시 연결할 수 있어야 한다.

1. **Candidate + applicability** - candidate/change-under-test identity와 `applicable` 판단
2. **Evaluation context** - retained case identity, quality-basis identity, 존재하는 경우 evaluation attempt/invocation/provenance reference
3. **Blocker + attribution** - failure stage/reason, candidate/shared/evaluation/unknown attribution을 재구성할 evidence와 uncertainty, revisit condition
4. **Baseline continuity** - current accepted baseline과 no-promotion을 explicit reference 또는 기존 durable decision chain으로 유일하게 재구성 가능

Baseline identity와 disposition을 매 blocker record에 독립 field로 중복 저장할 필요는 없다. 기존 durable decision chain에서 유일하게 복원되면 그 연결로 충분하다.

별도 scheduler, retry queue, incident workflow, baseline registry, failure taxonomy 또는 mandatory independent oracle은 필요하지 않다.

## Decision Criteria

| Criterion | Result |
| --- | --- |
| Invalid comparison을 decision으로 위장하지 않음 | `blocked/inconclusive`가 acceptance-stopping prerequisite failure를 별도로 보존한다. |
| Applicable candidate가 evaluation failure로 bypass하지 못함 | blocked 상태에서는 accept와 baseline promotion이 금지된다. |
| Candidate regression과 evaluation infrastructure failure를 구분 | status가 아니라 admissible attribution evidence와 comparison validity로 분류한다. |
| Durable decision chain과 baseline 의미 보존 | accept만 baseline을 승격하고 blocked는 last accepted baseline lineage를 유지한다. |
| 최소 복잡성 | 별도 scheduler/registry/workflow/statistical attribution framework를 요구하지 않는다. |

## Preservation And Transformation

- **A에서 보존** - `not-applicable`과 `blocked`의 분리, invalid comparison에서 fail-closed, candidate-attributable material failure의 reject 가능성, baseline no-promotion.
- **B에서 보존** - one-shot asymmetric failure로 attribution을 추측하지 않음, causal/bounded evidence requirement, case/basis와 revisit continuity, same-candidate resume 시 current comparability 재성립.
- **Transformation** - `reject vs blocked`를 runtime status taxonomy가 아니라 `admissible candidate attribution × comparison validity`로 재구성했다.
- **Removed** - `baseline success + candidate failure`만으로 stochastic failure attribution이 충분하다는 해석, blocker record마다 reconstructable baseline/disposition을 중복 저장해야 한다는 해석, mandatory independent oracle 요구.

## Residual Conditions

- **Limits** - stochastic provider behavior에서 attribution sufficiency의 fixed repetition/statistical rule은 없다. Human judgment variability가 남는다. T7은 emergency override semantics나 operational availability policy를 정의하지 않는다.
- **Trade-offs** - false reject를 줄이는 대신 ambiguous candidate regression이 blocked로 오래 남아 acceptance latency가 증가할 수 있다.
- **Cautions** - `blocked`는 waiver가 아니다. Human이 candidate 작업을 포기하는 것은 가능하지만 invalid comparison을 LLMOps quality `reject` evidence로 위장해서는 안 된다. Baseline retention도 baseline의 현재 품질·가용성 보증이 아니다. Resume 시 과거 partial evidence를 재사용해 false comparability를 만들지 않는다.
- **Reopen Conditions** - emergency override가 실제 requirement가 됨, provider/model nondeterminism 때문에 attribution이 반복적으로 불가능해 gate가 operational deadlock을 만듦, decision baseline과 operational-use baseline을 별도 정책으로 관리해야 할 필요가 생김, 또는 current comparability 재성립 규칙이 실제 운영에서 불충분하다는 failure evidence가 생김.
