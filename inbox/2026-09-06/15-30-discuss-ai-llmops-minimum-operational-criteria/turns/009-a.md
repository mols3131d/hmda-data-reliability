## Position

이제 `Same Case Retained` 자체를 더 정확히 정의해야 한다. 과거 invocation JSON을 보존하는 것만으로는 case가 retained됐다고 보기 어렵다. Invocation evidence는 **무슨 일이 실행됐는지**를 보존하지만, 다음 candidate에 적용할 **무엇을 기대해야 하는지**를 소유하지 않는다.

따라서 최소 LLMOps case에는 generated run evidence와 분리된 작은 authored/versioned definition이 필요하다.

## Proposal

첫 quality case의 최소 authored shape는 네 묶음이면 충분하다.

| Required definition | Minimum content |
| --- | --- |
| **case identity** | stable `case_id` 또는 stable path |
| **input definition** | 동일 case를 다시 만들 수 있는 canonical input 또는 deterministic input recipe/reference |
| **quality basis** | stable `rubric_id/version`과 사람이 판정할 수 있는 expectation |
| **control expectation** | material violation control = `FAIL`, compliant control = `PASS` |

여기에 invocation IDs, actual output, latency, token usage를 다시 넣지 않는다. 그것들은 run evidence가 소유한다. Human decision도 case definition에 덮어쓰지 않고 별도 decision evidence가 소유한다.

즉 ownership을 세 조각으로 분리한다.

```text
Authored Case Definition
  owns: input + rubric + control expectation

Invocation Evidence
  owns: actual run + provenance + output + operations

Decision Evidence
  owns: comparison + change-under-test + human decision
```

## Why this is minimum

다음 상태는 retained case가 아니다.

```text
invocation-1.json
invocation-2.json
human note: "uncertainty was okay"
```

과거 결과는 남아 있지만 다음 candidate가 같은 input과 같은 expectation을 사용했는지 검증할 stable case/rubric identity가 없다. 이 상태에서는 replay가 아니라 비슷한 실행을 다시 한 것일 수 있다.

반대로 case registry, database, eval service는 필요하지 않다. 하나의 tracked fixture 또는 작은 authored artifact가 stable identity와 content versioning을 제공하면 충분하다.

## Boundary

Case definition에 다음을 넣지 않는다.

- provider/model choice
- baseline/candidate invocation identity
- human decision
- deployment status
- aggregate pass rate
- owner/RBAC
- schedule
- production SLO

이 정보는 case의 expected behavior가 아니라 특정 실행 또는 운영 workflow의 상태다.

또한 `inbox` discussion artifact 자체를 canonical quality case로 삼는 것은 피해야 한다. Inbox는 non-canonical working artifact workspace이므로, 실제 구현 단계에서 case가 프로젝트 acceptance/evaluation contract가 된다면 owning source/test surface에 위치해야 한다. 다만 T4에서는 구체 경로를 결정하지 않는다.
