# Clarify Code 결정 기록

## 채택

| 결정 | 이유 | 영향 |
| --- | --- | --- |
| 기본 조사: 변경 대상·직접 호출부·관련 테스트 | 동작 계약 확인의 최소 범위 | 다른 경로 계약·공용 코드 영향 때만 확대 |
| 병목 우선순위: 분산 흐름, 책임 혼합, 숨은 정책, 복잡한 표현 | 큰 이해 비용부터 줄여 작은 변경으로 효과 확보 | 선행 병목 해소 후 낮은 순위 처리 |
| 병목을 해소하는 최소 해법 조합 선택 | 병목별 해법이 다름 | 이름·주석·함수 추출·제어 흐름 재구성 조합 |
| 독립 책임이 있고 호출부가 선명해질 때만 함수 추출 | 탐색 이동·불필요한 추상화 방지 | 독립 책임 없으면 구조 유지 |
| 관찰 가능한 동작을 보존 기준으로 사용 | 공개 API만으로 부족 | 반환값·예외·상태·부작용 순서·로그 의미 확인 |
| 기존 테스트 전후 실행, 미보호 동작에 최소 회귀 테스트 추가 | 같은 기준으로 동작 보존 확인 | 병목 주변 동작만 최소 보호 |
| 테스트 없으면 대체 검증과 한계 보고 | 검증 불가를 통과로 오인 방지 | 정적·타입 검사, 입출력 비교 활용 |
| 병목·변경·보존 근거·검증·위험 보고 | 변경 안전성 빠른 판단 | 짧게 쓰되 미검증 항목 공개 |
