# Directive

이 문서는 인간 주도의 규범적 기준선이다. 사용자의 명시적 요청 없이 수정하지 않는다.

## Purpose

Research를 통해 현재 상태, 불확실성, 영향 범위와 검증 가능한 근거를 확보한다.

Research는 다음 명세, 구현 또는 기술 판단을 지원하지만 요구사항·설계·구현을 대신 확정하지 않는다.

## Requirements

| ID | Requirement |
| --- | --- |
| R-01 | 하나의 핵심 목표와 필요한 하위 질문을 기준으로 조사해야 한다. |
| R-02 | 기존 근거를 먼저 재사용하고 부족한 부분만 조사해야 한다. |
| R-03 | 확인된 근거, 보조 자료와 가정을 구분해야 한다. |
| R-04 | 현재 환경과 버전에 맞는 직접 근거를 우선해야 한다. |
| R-05 | 다음 판단에 필요한 목표, 범위, 영향과 검증 기준이 확보됐는지로 완료를 판단해야 한다. |
| R-06 | 기존 Research 템플릿과 프로젝트 artifact 계약을 복제하지 않고 사용해야 한다. |
| R-07 | Arguments와 자동 해석 규칙을 `SKILL.md` 상단에서 쉽게 확인할 수 있어야 한다. |
| R-08 | 구조와 용어를 사람이 직접 읽고 수정할 수 있을 만큼 단순하게 유지해야 한다. |

## Invariants

- 특정 workflow, schema 또는 directory를 필수 의존성으로 만들지 않는다.
- Artifact 형식이나 경로를 근거 없이 새로 만들지 않는다.
- 충돌하는 근거를 임의로 합치거나 조용히 해소하지 않는다.
- 비공개 추론이나 chat transcript를 지속 가능한 근거로 저장하지 않는다.
- 불필요한 reference, script, template 또는 argument를 추가하지 않는다.

## Allowed Scope

| Area | Allowed |
| --- | --- |
| Repository | 관련 문서, 코드, 설정, 테스트, 실행 결과와 history 조사 |
| External | 현재 환경에 적용 가능한 공식 문서와 1차 자료 조사 |
| Execution | 안전한 읽기 전용(Read-only) 재현과 검증 |
| Artifact | 프로젝트의 기존 규칙과 템플릿에 따른 결과 생성·갱신 |

## Boundaries

- 요구사항, 설계와 구현 계획을 Research 결과로 확정하지 않는다.
- 코드·테스트·설정을 구현 목적으로 변경하지 않는다.
- 인접 개선을 현재 조사에 자동 포함하지 않는다.
- 근거 위치 또는 관찰 결과가 없는 주장을 사실로 기록하지 않는다.
- 제품 동작, 아키텍처, 비용이나 위험이 실질적으로 달라지는 선택은 사용자에게 돌린다.

## Decisions

| Decision | Rationale |
| --- | --- |
| 내부 필수 의존성을 두지 않는다. | 다른 workflow나 자산 변경이 Research 자체를 깨뜨리지 않게 한다. |
| 기존 프로젝트 템플릿과 artifact 계약을 사용한다. | 중복을 피하면서 프로젝트별 형식을 존중한다. |
| Arguments를 핵심 조사 제어로 제한한다. | 사용성을 유지하면서 설정 복잡도를 줄인다. |
| 별도 script와 reference를 만들지 않는다. | 현재 동작은 핵심 지침만으로 충분하다. |
