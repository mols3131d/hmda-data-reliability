# Directive

이 문서는 인간 주도의 규범적 기준선이다. 사용자의 명시적 요청 없이 수정하지 않는다.

## Purpose

Research를 통해 질문에 답할 수 있는 검증 가능한 근거와 불확실성의 경계를 확보한다.

Research는 다음 명세, 구현 또는 기술 판단을 지원하지만 요구사항·설계·구현을 대신 확정하지 않는다.

## Requirements

| ID | Requirement |
| --- | --- |
| R-01 | 하나의 핵심 목표와 필요한 하위 질문을 기준으로 조사해야 한다. |
| R-02 | 기존 근거를 먼저 재사용하고 답이나 주요 불확실성을 바꿀 수 있는 부분만 추가 조사해야 한다. |
| R-03 | 현재 환경과 버전에 맞는 직접 근거와 1차 자료를 우선해야 한다. |
| R-04 | 중요한 결론은 다시 확인할 수 있는 근거 위치와 연결해야 한다. |
| R-05 | 남은 불확실성이 사용 목적을 막는지로 완료를 판단해야 한다. |
| R-06 | 기존 Research 템플릿과 프로젝트 Artifact 계약을 복제하지 않고 사용하며, 필수 항목과 조사 목표에 관련된 항목을 근거로 채워야 한다. |
| R-07 | 사용자는 `README.md`, 실행자는 `SKILL.md`, 상세 실행 지식은 `references/`, 개발 기준은 `docs/`에서 확인할 수 있어야 한다. |
| R-08 | 구조와 용어를 사람이 직접 읽고 수정할 수 있을 만큼 단순하게 유지해야 한다. |

## Invariants

- 특정 workflow, schema 또는 directory를 필수 의존성으로 만들지 않는다.
- 위험을 다루기에 충분한 가장 낮은 엄밀도를 사용한다.
- 새로운 조사가 답이나 불확실성을 실질적으로 바꾸지 않으면 중단한다.
- 템플릿 항목을 채우기 위한 추가 조사는 현재 Research 목표와 관련된 범위로 제한한다.
- Artifact 형식이나 경로를 근거 없이 새로 만들지 않는다.
- 확인하지 못한 내용을 추측하여 템플릿을 채우지 않는다.
- 충돌하는 근거를 임의로 합치거나 조용히 해소하지 않는다.
- 비공개 추론이나 Chat transcript를 지속 가능한 근거로 저장하지 않는다.
- 같은 규칙을 여러 문서에서 반복하지 않는다.

## Content Ownership

| Location | Responsibility |
| --- | --- |
| `README.md` | 사용자용 소개, Arguments와 예시 |
| `SKILL.md` | 실행에 항상 필요한 최소 지침과 참조 경로 |
| `references/workflow.md` | 범위, 엄밀도, 조사 절차와 종료 기준 |
| `references/evidence.md` | 근거 품질, 분류, 충돌과 추적성 |
| `references/output.md` | 완료 상태, 출력 방식, 템플릿 적용과 이식성 |
| `docs/DIRECTIVE.md` | 인간이 유지하는 목적, 요구사항과 불변 조건 |
| `docs/WORKING.md` | 현재 구조, 검증 상태와 남은 작업 |

## Boundaries

- 요구사항, 설계와 구현 계획을 Research 결과로 확정하지 않는다.
- 코드·테스트·설정을 구현 목적으로 변경하지 않는다.
- 인접 개선을 현재 조사에 자동 포함하지 않는다.
- 근거 위치 또는 관찰 결과가 없는 주장을 확인된 사실로 기록하지 않는다.
- 제품 동작, 아키텍처, 비용이나 위험이 실질적으로 달라지는 선택은 사용자에게 돌린다.

## Decisions

| Decision | Rationale |
| --- | --- |
| `SKILL.md`를 얇게 유지한다. | 반복 로딩 비용과 수정 난이도를 줄인다. |
| 상세 지침을 `references/`로 분리한다. | 필요한 지식만 읽는 점진적 공개(Progressive Disclosure)를 적용한다. |
| 사용자 설명은 `README.md`가 소유한다. | 실행 지침과 사용자 문서를 분리한다. |
| 개발 기준과 상태는 `docs/`가 소유한다. | 운영 지침과 유지보수 정보를 섞지 않는다. |
| 기존 프로젝트 템플릿을 출력 계약으로 사용한다. | 프로젝트별 형식을 존중하고 필요한 내용을 누락하지 않으면서 템플릿이 조사 자체를 지배하지 않게 한다. |
