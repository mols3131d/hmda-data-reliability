# Clarify Code

## Essence

`pivot-clarify-code`는 **기존 동작을 보존하면서 코드 이해 부채를 줄이는 스킬**이다.

코드를 전반적으로 더 좋게 만드는 것이 목적이 아니다. 잘못 이해했을 때 비용이 큰 읽기 병목을 찾아 가장 작은 안전한 변경으로 해소한다. 호출자는 구현을 깊게 읽지 않아도 필요한 사용 의미를 알 수 있어야 하고, 유지보수자는 코드에서 의도와 제약을 복원할 수 있어야 한다.

- **동작을 보존한다.** 이해 개선과 기능 변경이 섞이면 무엇이 명확해졌고 무엇이 달라졌는지 구분하기 어려워지기 때문이다.
- **가장 중요한 병목 하나를 먼저 해소한다.** 이해 부채의 크기는 코드 양보다 오해가 만드는 비용으로 판단하며, 전면 정리는 새로운 위험과 검토 비용을 만든다.
- **가장 작은 안전한 변경을 선택한다.** 가독성을 높이기 위해 설명·추상화·구조를 불필요하게 늘리면 새로운 이해 부채가 생기기 때문이다.
- **의미를 필요한 곳 가까이에 둔다.** 호출 의미는 API 가까이, 구현 이유는 코드 가까이, 넓은 정책은 공식 소유 문서에 두어 중복과 불일치를 줄인다.
- **기존 근거에서 의미를 복원한다.** 호출부, 관련 테스트와 현재 동작은 중요한 단서지만, 테스트를 요구사항이나 공식 계약의 최종 근거로 대신하지 않는다.
- **다른 품질 문제를 흡수하지 않는다.** 정확성 리뷰, 아키텍처 재설계, 저장소 탐색, 포괄적 문서화가 주된 문제라면 별도 작업으로 분리해 스킬의 책임을 보존한다.
- **병목이 해소되면 멈춘다.** 더 정리할 수 있다는 이유만으로 범위를 넓히면 코드 명확화가 일반적인 리팩터링 작업으로 변하기 때문이다.

새 규칙이나 기능은 이 본질을 더 잘 수행하게 할 때만 추가한다. 이 본질을 넓히거나 다른 품질 작업을 흡수하게 만든다면 추가하지 않는다.
