## Context

- 1단계에서 데이터 신뢰성 인시던트 관련 모델 규약(Pydantic)이 수립되었습니다.
- 품질 이상 탐지기(Detector)와 LangGraph 기반 RCA 에이전트의 로컬 검증 및 오프라인 테스트를 진행하려면, 실제 소스 레벨에서 다양한 오류를 내포한 물리 파티션 데이터셋이 DuckDB 데이터베이스 상에 존재해야 합니다.
- 따라서 원천 데이터(`data/raw/tlc`)를 읽어 정상 및 4가지 합성 이상치 데이터셋을 생성하고, 로컬 DuckDB 및 디스크에 구조화된 파티션 형태로 배포하는 설계가 필요합니다.

## Goals / Non-Goals

**Goals:**
- 로컬 DuckDB 데이터베이스 연결 관리 및 테스트 병렬 실행 시 파일 잠금이 방지되는 테스트 격리 아키텍처 설계.
- 원본 Parquet 파일로부터 일자별 분포를 보존하며 4가지 품질 이상 케이스(볼륨 급감, Null 급증, 스키마 변형, 지연)가 가공 주입된 파티션 파일 세트를 생성하는 Generator 유틸리티 작성.
- 로컬 DuckDB 상에 생성된 각 파티션을 독립적으로 격리하여 적재하고, 올바르게 데이터가 조회되는지 검증하는 단위 테스트 작성.

**Non-Goals:**
- Dagster 오케스트레이션과 연계된 자동화 파이프라인 구축 (3단계에서 진행).
- dbt Core를 통한 스테이징 및 마트 모델링 변환 (4단계에서 진행).
- 3단계에서 구현할 멱등(Idempotent) 오버라이트 적재 기능 자체의 사전 중복 구현. (2단계는 파일 생성 및 쿼리 인터페이스 토대에 집중)

## Decisions

- **DuckDB 연동 아키텍처 및 테스트 격리**: 
  - 파이썬 `duckdb` 라이브러리를 직접 호출하는 간단한 데이터베이스 연결 관리자(Context Manager)를 정의합니다.
  - pytest-xdist를 이용한 **병렬 테스트 실행 시 파일 잠금(Locking) 충돌을 방지**하기 위해, 테스트 세션에서는 pytest의 `tmp_path` 픽스처를 바인딩하여 각 프로세스별로 독립된 임시 `.db` 파일 경로를 사용하도록 강제하거나 인메모리 세션을 활성화합니다.
- **파티션 친화적 합성 데이터 샘플링**:
  - raw Parquet 파일을 읽을 때 단순 헤더 10,000행 슬라이싱은 날짜 편향을 발생시킵니다. 대신, 원본 파일 내에서 고유한 일자별 파티션 날짜를 고르게 추출하여 일자 단위별로 정해진 비율의 행을 샘플링하는 로직을 적용합니다.
  - 이를 통해 데일리 파티셔닝 구조를 안전하게 보존하며 품질 결함을 주입합니다.
    - *Row Count Drop*: 파티션별 샘플링(`sample(frac=0.1)`)을 통해 행 개수를 90% 이상 유실시킵니다.
    - *Null Spike*: 특정 중요 열(`total_amount` 등)의 일부 값을 강제로 `NaN`으로 치환하여 Null 비율을 급증시킵니다.
    - *Schema Drift*: 특정 컬럼의 이름을 바꾸거나 데이터 타입을 텍스트로 캐스팅합니다.
    - *Freshness Delay*: 관측 타임스탬프(`observed_at`)를 현재 시스템 시간 대비 고의로 과거 시점으로 밀어 넣어 SLA 지연을 재현합니다.
  - 가공 완료된 데이터는 디스크의 격리된 파티션 디렉터리(`data/lakehouse/cases/<case_name>/`) 아래에 Parquet 파일 형태로 영속화하여, 향후 Ingestion 및 dbt 단계가 이 파일들을 소스로 읽어갈 수 있도록 유연성을 부여합니다.

## Risks / Trade-offs

- **[Risk] DuckDB 파일 동시성 잠금 (Locking)** 
  - DuckDB 파일 모드는 여러 테스트 프로세스가 병렬 작동할 때 쓰기 권한 충돌 에러가 발생합니다.
  - *[Mitigation]*: 병렬 테스트 시에는 각각 격리된 고유 경로에 임시 `.db` 파일을 동적으로 생성하여 사용하고, 사용이 끝난 후 커넥션을 확실하게 종료(close)해 주는 teardown 장치를 마련합니다.
- **[Risk] 대용량 메모리 점유**
  - raw Parquet 파일의 용량이 크기 때문에 Pandas DataFrame으로 통째로 읽어올 경우 테스트 속도 저하 및 메모리 부족 현상이 일어날 수 있습니다.
  - *[Mitigation]*: 결함 데이터를 생성할 때 전체 파티션 날짜가 분포하는 범위 내에서 핵심 청크만 추출하여 변형 데이터를 신속하게 생성하고 로컬 메모리 사용량을 최소화합니다.
