## MODIFIED Requirements

### Requirement: 매개변수 기반의 파티션 개별 적재 실행

시스템은 특정 HMDA 원천 파티션(예: `activity_year=2024` 또는 특정 원천 파일명)을 명시적인 매개변수 인수로 주입받아 해당 파티션 데이터만 격리하여 인제스션을 실행해야 한다(SHALL).

#### Scenario: 특정 HMDA 연도 파티션 단독 구동

- **WHEN** 적재 실행 함수가 `2024` 연도 파티션 키를 입력인자로 전달받아 실행될 때
- **THEN** 원천 데이터 중 `activity_year`가 2024인 레코드들만 필터링되어 적재 대상이 되어야 한다.

#### Scenario: 특정 HMDA 원천 파일 단독 구동

- **WHEN** 적재 실행 함수가 HMDA 원천 파일명을 입력인자로 전달받아 실행될 때
- **THEN** 해당 원천 파일에서 읽은 레코드만 적재 대상이 되어야 한다.

### Requirement: 이상치(Outlier) HMDA 데이터 보존

시스템은 파티션 분류 시 소득, 대출 금액, 지역 코드, action code가 비정상적인 범위를 벗어나는 품질 이상치 데이터 행들도 폐기하지 않고 파티션 테이블에 그대로 보존하여 적재해야 한다(SHALL).

#### Scenario: 비정상 HMDA 값 적재 검증

- **WHEN** 입력 파일에 음수 소득, 비정상적으로 큰 대출 금액, 알 수 없는 지역 코드 같은 이상치 행들이 존재할 때
- **THEN** 해당 행들은 버려지지 않고 적재 대상 데이터 세트에 안전하게 포함되어 품질 감지 대상 evidence로 적재되어야 한다.

### Requirement: 멱등성 보장 덮어쓰기(Idempotent Overwrite)

시스템은 동일 HMDA 연도 또는 동일 원천 파일 파티션 데이터에 대해 중복 인제스션 실행 시 데이터 유실이나 누적이 없도록 기존 파티션을 오버라이트하여 멱등성을 보장해야 한다(SHALL).

#### Scenario: 동일 HMDA 연도 파티션 재적재

- **WHEN** `2024` HMDA 연도 파티션 데이터 적재를 2회 연속 수행할 때
- **THEN** 2회 실행 후에도 DuckDB 테이블에 중복 저장된 행이 없어야 하며, 2024 파티션의 최종 데이터 건수가 1회 실행 결과와 일치해야 한다.

#### Scenario: 동일 HMDA 원천 파일 재적재

- **WHEN** 동일 HMDA 원천 파일 적재를 2회 연속 수행할 때
- **THEN** 2회 실행 후에도 해당 `source_file`의 최종 데이터 건수가 1회 실행 결과와 일치해야 한다.
